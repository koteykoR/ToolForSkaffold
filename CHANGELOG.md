# Изменения

## 0.1.0-preview.10

- Удалён неиспользуемый `StubGetAsync`; для JSON-ответа используется `StubAsync` с `RequestMatch` и `StubResponse.Json`.

## 0.1.0-preview.9

- Удалены `StubWithBodyAsync` и строковые перегрузки поиска/ожидания. Составные условия передаются через `RequestMatch`.
- `FindRequestBodiesAsync<T>` явно возвращает десериализованные тела; `FindRequestsAsync` — полные записи журнала.
- `IgnoreUrlCase` заменяет `IgnorePathCase` и действует на выбранное условие пути либо полного URL.
- `StubGetAsync` и `StubGetFileAsync` оставлены как короткие методы GET по пути без общего `ignoreCase`.

## 0.1.0-preview.8

- Общий WireMock API: `RequestMatch` используется для регистрации, поиска и ожидания, `StubResponse` задаёт JSON, текст, байты или ответ без тела.
- Независимые настройки регистра пути/URL, тела и значений заголовков; сопоставление заголовков при регистрации.
- Настройки JSON ответа и передача готового `HttpClient` с явным владением. Прежние методы сохранены как обёртки.

## 0.1.0-preview.7

- WireMock сопоставляет пути/URL, тела и значения заголовков с учётом регистра. Параметр `ignoreCase: true` явно отключает учёт регистра для конкретного вызова регистрации, поиска или ожидания.

## 0.1.0-preview.5

- `IAsyncFixture` наследует стандартный `IAsyncDisposable`: собственный `DisposeAsync` должен возвращать `ValueTask`. `FixtureTest` больше не требует и не вызывает `IDisposable`.
- `ObserveAsync` разделяет интервал наблюдения и лимит каждой проверки (`checkTimeout`). Незавершённая проверка вызывает `TimeoutException`.

## 0.1.0-preview.3

- Первый состав из пяти пакетов: общие HTTP/NUnit/Allure-инструменты, WireMock, Kafka, PostgreSQL и MongoDB.
- Ограниченное ожидание с отменой, изолированная очистка ресурсов, диагностика запросов.
- Общая библиотека отделена от контрактов и конфигурации сервиса.
- Пакеты включают portable PDB со встроенными исходниками.
- Локальная предварительная версия; публикация во внутренний feed не настроена.
